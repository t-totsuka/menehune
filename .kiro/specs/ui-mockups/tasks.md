# Implementation Plan

> **進め方の前提**
> - タスク 1〜7 で、全画面をワイヤーフレーム段階でレビューでき、機械的な検査が回る状態にする。
> - タスク 8（ハイフィデリティの仕上げ）は、人によるワイヤーフレームのレビューを終え、画面レジストリで全画面のワイヤーフレームが approved になってから着手する（要件 1.3、1.4）。
>
> **並列化の注意**
> - UI 文言の辞書（日英）とサンプルデータは、それぞれ 1 つのファイルにまとまっている。そのため、文言やデータを追加するタスク（3、4、5）は並列にしない。
> - カタログページ（6）は、辞書を読むだけで編集しない。文言は日本語の固定とし、ページ固有のスタイルはページ内に書く。

  - JS の型検査の設定（checkJs、strict、出力なし）と、設計にある全データ・部品の契約の型定義を置く。対象は、画面レジストリ、辞書、用語集、サンプルデータ、表示状態、部品の属性、検査の設定
  - 依存パッケージとレビュー用スクリーンショットの保存先を Git の管理外にする。開き方・URL パラメータ・検査の実行方法を書いた README を置く
  - 完了状態：依存をインストールした状態で型検査がエラーなく終わり、パッケージ定義に上記のスクリプトがすべてある

- [ ] 1.5 初期テーマの決定と表示状態の管理を作る

  - 許可されていない値は既定値にし、警告として取り出せるようにする。保存に失敗しても無視し、URL だけで動作する
  - 状態の更新では URL を書き換え、再読み込みせずに通知を再発行する
  - 画面 ID がないページ（見本ページなどのカタログページ）では、すべてのログイン状態とシナリオを許可する
  - 完了状態：見本ページを `?lang=en&theme=dark&stage=foo&scenario=weather-failed` で開くと、ルート要素が英語・ダーク・weather-failed になる。段階は hifi に戻り、警告が 1 件記録される

  - 完了状態：見本ページを `?lang=en` で開く、または状態の更新で言語を変えると、文言と日付表記が切り替わる。存在しないキーは印付きで表示される

- [ ] 2. 静的検査スクリプト
- [ ] 2.1 (P) 画面レジストリの検査を作る
  - 次の点を検査する
    - 15 の画面 ID がそろっている
    - 各画面のファイルが存在し、ファイル内の画面 ID と一致する
    - シナリオの先頭が default である

  - 違反は「ファイル:行 内容」の形式で出し、1 件でもあれば終了コード 1 にする
  - 完了状態：現在のレジストリでは終了コード 0。わざと不変条件に違反させると、違反が報告されて終了コード 1 になる
  - スクリプトは他の検査スクリプトと共有の補助モジュールを持たず、単独で完結させる（並列に作るため）

  - スクリプトは他の検査スクリプトと共有の補助モジュールを持たず、単独で完結させる（並列に作るため）

- [ ] 2.3 (P) コントラストの検査を作る

  - 完了状態：基準を満たさない組があると、組・テーマ・実際の比が報告されて終了コード 1 になる。初期案のトークンでの結果が出力される
  - スクリプトは他の検査スクリプトと共有の補助モジュールを持たず、単独で完結させる（並列に作るため）

## Implementation Notes
- テストの方針（実装開始時に親が補足）：純粋なロジック（表示状態の解決、文言の置換、日付の書式、検査スクリプトの判定）は、Node 標準のテストランナー（`node --test`、`mockups/tests/unit/*.test.mjs`）で検証する。classic script は `node:vm` に `window` 相当のグローバルを与えて読み込む。DOM やブラウザでの振る舞いは、7.1 より前でも Playwright のテスト（`mockups/tests/*.spec.mjs`）を追加してよい。その場合、Chromium のインストールを前倒ししてよい（7.1 は設定ファイルと共通の仕組みを担う）
- 開発環境：Windows の Node v26、npm 12。Git のブランチは `feat/ui-mockups`
- 1.1：部品の基底は types.d.ts で `MockElementContract`（interface）と `MockElementConstructor` として宣言されている。render/sample/t は public の契約なので、base.js で JSDoc の `@protected` を付けると `window.MockElement` の代入が型エラーになる。public のまま実装する（types.d.ts の「protected」というコメントは、4.1 で実態に合わせて直す）
- 1.2：E2E には Chromium が必要（`npx playwright install chromium` は実行済み）。`mockups/playwright.config.mjs` は testMatch を `tests/*.spec.mjs` に絞った最小構成で、7.1 で最終形にする。check-tokens（2.2）は `%` を検出対象にしない（base.css の `max-width: 100%` を許容する）。全要素に `min-width: 0` のリセットがあるので、縮んでほしくない部品は明示的に最小サイズを指定する
